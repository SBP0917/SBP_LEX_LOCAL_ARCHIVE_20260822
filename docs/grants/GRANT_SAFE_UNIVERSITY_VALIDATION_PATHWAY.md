# Grant-Safe University Validation Pathway

Status: draft for owner review.

This pathway is designed to support future university validation discussion
without exposing source code, full architecture, full blueprints, SKG/DTN
mechanics, EIE implementation mechanics, token/gate internals, or trust deed
content.

## Pathway

1. First contact uses redacted, non-enabling summaries only.
2. No source code, command packs, full reports, blueprints, or repository archive
   are sent at first contact.
3. Before technical disclosure, the reviewer or institution accepts written
   confidentiality terms or an NDA pathway.
4. The owner approves named reviewers before technical material is shared.
5. Technical material is watermarked, recipient-specific, hash-manifested, and
   transmission logged.
6. Student access is not allowed unless separately approved by the owner.
7. Publication, redistribution, public upload, teaching use, derivative use, and
   ownership/licence transfer are not authorised.
8. Full repository handover is not the default pathway.
9. Reviewer feedback is requested privately and should state whether selected
   bounded claims are supported, unsupported, overbroad, ambiguous, or require
   narrowing.

## First-Contact Material

Allowed:

- grant-safe cover summary
- grant-safe scope/exclusions summary
- grant-safe validation questions
- owner-approved non-enabling screenshots if needed

Not allowed:

- source code
- full reports
- full blueprint content
- rebuild-level architecture
- technical commands
- attack reports
- hash indexes
- deployment notes
- final pilot package material

## Later Confidential Material

Later confidential material may include selected validation summaries and
reviewer-facing evidence extracts only after owner approval.

## Status Boundary

University validation is intended but has not occurred. This pathway is a
controlled preparation route, not a validation result.
